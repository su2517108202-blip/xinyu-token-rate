# 心语 Token 速率

输入框上方的一条速率仪表。读数全部来自当前会话已经载入的数据，不发请求、不上报、不另存历史。

## 显示什么

整条只有一行：状态标记、速率、8 秒吞吐曲线，以及解释这个数字的几个读数。

| 读数 | 含义 |
| --- | --- |
| **速率** | 生成中是最近一秒窗口的补全 token 速率；结算后换成服务端上报的真实值 |
| **曲线** | 40 根 200 毫秒的柱子，按观测到的带宽自适应缩放，稳定输出也能看出形状 |
| **本步** | 当前或最近一步的输出 token |
| **首字** | 从步骤开始到第一个字的等待时间，`~` 表示估算 |
| **缓存** | 计费输入中命中缓存的比例 |
| **上下文** | 相对于上下文窗口的占用压力 |

## 交互

- 点整条任意位置打开详情面板；再点一次、按 `Escape` 或点面板外来关闭。
- 在曲线上拖动可读到任意一根柱子的速率，松手回到窗口均值与峰值。
- 点「最近步骤」里的任意一行可把它钉到大读数上，再点一次解除。
- 任何宽度下都保持 36 像素高，窄屏从右往左收起读数，并遵循 `prefers-reduced-motion`。

## 数字从哪来

生成中的数字由流式字符按字符类别（中日韩、拉丁、数字、代码标点）折算，再用本会话已完成步骤上报的用量做 ridge 校准。回放 1317 个步骤，估算误差中位数 **5.7%**，实时窗口速率 **3.6%**。

回放的步骤没有首字时间戳——宿主只在实时流里记录它——所以结算后的解码窗口由步骤时长、输出量和提示量重建。对 1346 个步骤做留一会话交叉验证，误差中位数 **25%**；直接用整段步骤窗口则是 59%。凡是估算出的值都带 `≈` 前缀。每行的 token 数仍然是服务端上报的真实值，所以即使速率有估算，累计量也是准的。

## 动画怎么跑

动效全部是 CSS 的组合动画（`opacity`、`transform`），没有 canvas、没有逐帧 JS 计算。唯一按时间重算的是 200 毫秒一次的采样，而它只在模型正在输出时才跑：空闲、结算完成和错误三个状态完全静止，浏览器主线程占用是 0%。窗口隐藏时连采样也不再提交渲染。

- 每秒一次的读数缓动只在整数位变化时才提交，屏幕上看到几位数就渲染几次。
- 整条停靠栏只保留一个无限循环动画，其余用静止的透明度差表示状态。
- 曲线两端的渐隐由描边渐变实现，不是容器 mask；毛玻璃只保留在浮层面板上，停靠栏用的是 94% 不透明的表面色。

## 性能

| 状态 | CPU（相对无插件页面） | 说明 |
| --- | --- | --- |
| 空闲 / 已结算 / 出错 | **0%** | 完全静止，没有任何动画在跑 |
| 正在输出 | ~3–4% | 曲线与波头，即"还在动"的那一个循环 |
| 等待首字 / 工具运行 | ~3–4% | 发丝线缓慢呼吸 |

占用的内存是一次性的 DOM 与样式，没有随运行时间增长的结构。数字是 2× 缩放下单个标签页的增量（GPU 合成开启），实测基准页面本身就有 3% 左右的渲染开销。

## 说明

- 只统计当前会话，切换会话即重置曲线。
- 数据不出页面：插件只注册一个停靠位和一个文案命名空间。
